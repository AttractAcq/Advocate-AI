# Phase 4 read-only intelligence gate

**Status: open.** The synthetic software path is implemented, but the exit gate requires representative alerts in an **independent Wazuh installation** with evidence and explanation. No independent Wazuh host, offline collection trace, or independent security/QA sign-off is available yet. This record does not claim AT-11, AT-12 or T-021 complete.

The merged PR #10 baseline passed all 39 local tests and GitHub quality, secrets and dependency checks. This follow-up query, identity, model-format and outage-simulation change passed all 47 local tests and the Console build. A later [one-run local Qwen contextual evaluation](contextual-answer-evaluation.json) records a model answer using two cited fictional alert IDs, with an out-of-window alert and injected related text excluded. A [four-case local model matrix](contextual-answer-matrix.json) checks the five-related-alert cap, exact cited timestamps, no-related and unmapped cases, and an instruction-like primary alert. An earlier matrix run surfaced an unsupported 30-minute duration; the prompt now asks for supplied timestamps and Core's output guard rejects common duration phrases and clock times absent from cited alerts. These are code and model checks on an Apple Mac, not G2 host or WAN evidence. The sample FortiGate destination uses a documentation IP and the asset registry is fictional. The local simulation cannot prove that Wazuh collected an event.

The Wazuh alert reader targets the [Indexer alert search API](https://documentation.wazuh.com/current/user-manual/indexer-api/use-case.html) (`wazuh-alerts*`), because alerts are stored in the indexer. [Wazuh's alert example](https://documentation.wazuh.com/current/getting-started/use-cases/vulnerability-detection.html) shows the index document `_id` and Wazuh `_source.id` are distinct; both are now kept in evidence. OpenSearch documents [filtering by index name](https://docs.opensearch.org/latest/field-types/metadata-fields/index-metadata/) when searching multiple indices. FortiGate fixture shape follows the [FortiOS log field reference](https://docs.fortinet.com/document/fortigate/7.0.0/fortios-log-message-reference/357866/log-message-fields). A read-only indexer account, network policy and certificate validation must be checked on the actual lab host.

Phase 4 can proceed on local synthetic data while hardware acquisition is paused. The gate remains open until the independent monitoring and resilience evidence exists and the assigned external reviewer records a decision.
