# Coordinated synthetic vessel recovery set

The vessel recovery capture requires a stopped, signed installation. It holds the vessel operation lock and the policy directory lock, verifies that only the labelled Knowledge data volume remains, freezes the approved Core sources, policy, audit chain and SQLite history, then starts the signed Knowledge image on that volume without network access. The signed Core image checks the complete document index against the frozen source bytes. A bounded PostgreSQL custom dump and the frozen Core files enter one encrypted restic snapshot. An Ed25519 receipt signs the snapshot ID, release and installation IDs, source and passage counts, audit checkpoint and dump hash.

Restoration first verifies the receipt and encrypted repository, then restores into a new directory. It checks every restored source, policy, audit checkpoint, SQLite integrity and dump hash against the receipt. The Linux signed-image rehearsal additionally restores the dump into a clean, networkless PostgreSQL container and uses the signed Core image to compare the recovered Knowledge index to the recovered files. The rehearsal uses temporary trust authentication solely inside an isolated, disposable synthetic database.

The operator entry point exposes `capture-recovery-set`, `verify-recovery-receipt` and `restore-recovery-files` through `python -m scripts.vesselctl --help`. Capture requires a previously completed `stop` and `finish-stop`, approved restic binary digest, private staging and password files, a signing key, and a new receipt path. `restore-recovery-files` creates a new directory containing verified Core files and the PostgreSQL custom dump; it does not activate that directory as a vessel installation.

The capture is a bounded synthetic candidate: at most 120 approved sources, a 16 MiB PostgreSQL dump, 16 MiB audit trail and 256 MiB conversation database. It does not activate a restored vessel or restore production role credentials and privileges. Production recovery needs a separately reviewed role/credential procedure, restore transaction and rollback design, target-hardware rehearsal, operator runbook, and independent security review. Signing and restic keys remain outside the snapshot and need separate custody. A local repository is not an off-vessel copy.
