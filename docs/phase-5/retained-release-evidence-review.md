# Offline review of retained release CI evidence

The `synthetic-three-image-bundle-evidence` artifact contains `result.json`,
three Core/Console/Knowledge scan and SBOM pairs, the updated Core pair, and
small detached signature proofs for the initial and updated vessel manifests.
The verifier checks the recorded SHA-256 of `result.json`, its reported
synthetic release and recovery outcomes, and all four scan/SBOM pairs using
the existing offline release intake policy. For artifacts created after the
manifest-proof change, it also checks both Ed25519 signatures against the
retained synthetic public key, binds that key and the manifest hashes to
`result.json`, and compares signed image inventory hashes to the scan/SBOM
results. It rejects changed result bytes,
duplicate JSON keys, missing recovery results, unmatched image hashes, stale
or unresolved inventories, and high, critical or unknown scan findings.

After downloading the named artifact from a specific final-head GitHub Actions
run, compare the run's head SHA with the blocker record and use its recorded
result hash. For example, PR #262 at `21947f0` used run `44988888711`:

```sh
gh run download 44988888711 \
  --name synthetic-three-image-bundle-evidence \
  --dir /private/lab/evidence/pr262
.venv/bin/python -m scripts.phase5_verify_ci_release_evidence \
  --directory /private/lab/evidence/pr262 \
  --result-sha256 efb46340bda9de392b38c7977ad8c2b2122776101b32b62c05d5d0312dd7a8b0
```

This returned `artifact-consistency-pass` and
`signed_manifests=initial-and-updated-verified`. The previous verifier, at its
original commit, was run against downloaded final-head artifacts for PR #255
(run `44972817825`, result hash
`6f066939f27320b68e0a45bc961b6493895c53df40dd2129114d9e2ed2a26da5`)
and PR #256 (run `44974524081`, result hash
`ca71025a2e83acd3020c92cfec45e6cb84d4c5eb471cfe55c3f0afb2fa36bb01`).
All three returned `artifact-consistency-pass` with four checked image pairs.
The verifier applies the release intake's current 30-day scan freshness rule;
a historical artifact can remain authentic while no longer being eligible as
a current release candidate.

**Scope.** Earlier artifacts lack detached signatures and require the verifier
from their original commit. The new artifact retains signed manifest controls,
but neither image archive bytes nor the complete release bundle. The synthetic
public key is generated by the CI rehearsal and carried in the same artifact;
an externally trusted release key is not established. This command verifies
the retained signatures and inventory consistency, not the archive bytes,
runner identity, hardware behavior, deployment approval or independent product
assessment. Preserve the GitHub run URL, final head, artifact hash and
reviewer decision separately.
