# Repository controls for Phase 1

The `main` branch is published at [AttractAcq/Advocate-AI](https://github.com/AttractAcq/Advocate-AI). The [CI workflow](../../.github/workflows/ci.yml) runs the synthetic lab and Core tests, builds the Console, scans full Git history with Gitleaks, verifies the Python lock, and audits Python/npm dependencies on pull requests. Gitleaks 8.24.3 is downloaded with a pinned SHA-256 because its GitHub Action failed on the initial root-commit range. GitHub's native dependency-review action is unavailable because the private repository does not have the required Dependency graph and Advanced Security features enabled. The replacement gate checks `uv.lock` and the hashed `requirements.lock` with pip-audit, plus `package-lock.json` with npm audit. [Dependabot](../../.github/dependabot.yml) monitors GitHub Actions, Python and npm manifests. Actions are versioned or pinned in the workflow; before a production release, resolve all remaining action tags to full commit SHAs and review action provenance.

Configure `main` protection: require pull requests, at least one independent approving review once a second reviewer is available, dismiss stale approvals, require the `quality`, `secrets` and `dependency-review` checks, prohibit force pushes and deletions, restrict bypass, and require conversation resolution. Add valid CODEOWNERS identities for security-sensitive paths when those identities are known. Enable repository secret scanning, push protection and GitHub-native dependency review if the account plan supports them. Confirm the settings through the remote UI before G0A.

Create release tags only from reviewed commits after CI passes. Phase 1 does not publish a software release. Signed bundles and rollback belong to Phase 5.
