# Repository controls for Phase 1

The `main` branch is published at [AttractAcq/Advocate-AI](https://github.com/AttractAcq/Advocate-AI). The [CI workflow](../../.github/workflows/ci.yml) runs a dependency-free build and unit tests, a synthetic lab smoke test, a full-history Gitleaks scan, and a pull-request dependency gate. The first push exposed a Gitleaks Action error on the root commit's Git range. The workflow now downloads Gitleaks 8.24.3 with a pinned SHA-256 and scans the complete history directly. GitHub's dependency-review action failed because the private repository does not have the required Dependency graph and Advanced Security features enabled. The dependency gate now fails if the currently dependency-free Phase 1 manifest acquires runtime dependencies; a reviewed lockfile and vulnerability scan must be added when dependencies are introduced. [Dependabot](../../.github/dependabot.yml) is configured to monitor GitHub Actions and Python manifests. Actions are versioned in the workflow; before a production release, resolve and pin full commit SHAs and review action provenance.

Configure `main` protection: require pull requests, at least one independent approving review once a second reviewer is available, dismiss stale approvals, require the `quality`, `secrets` and `dependency-review` checks, prohibit force pushes and deletions, restrict bypass, and require conversation resolution. Add valid CODEOWNERS identities for security-sensitive paths when those identities are known. Enable repository secret scanning, push protection and GitHub-native dependency review if the account plan supports them. Confirm the settings through the remote UI before G0A.

Create release tags only from reviewed commits after CI passes. Phase 1 does not publish a software release. Signed bundles and rollback belong to Phase 5.
